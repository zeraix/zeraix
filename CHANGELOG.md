- **[2026-10-19 · v2.3.4]** Fixes the Windows packaged app's `runtime exited (code=3221225786)` error (`0xC000013A`, `STATUS_CONTROL_C_EXIT`): a command that broadcast Ctrl+C to the console it shared with the Rust runtime used to terminate the runtime mid-turn along with its services. Commands and stdio MCP servers now run on their own hidden console (`CREATE_NO_WINDOW`), and the runtime ignores console Ctrl+C / Ctrl+Break (host-controlled shutdown only; child commands still stop on Ctrl+C, and manual terminal runs are unchanged). Adds a Windows-only regression test. [Release notes](https://github.com/zeraix/zeraix/releases/tag/v2.3.4)
- **[2026-10-12 · v2.3.3]** Improves context handling in long turns: the in-progress turn is no longer trimmed to fit the working-set budget (only the model's real context window can cut it), so the agent stops dropping files it just read and re-reading them; unseen tool results are removed last and assistant prose is shortened before user messages. Removed tool results can now be recovered by id through a new `recall_tool_result` call (with `offset`/`limit` paging) instead of re-running the command, token accounting is calibrated against the provider's reported prompt tokens, and summaries are built from the original tool output rather than "removed" placeholders. Queued messages sent while the agent is generating now have their own list UI with per-item removal. Also a large internal refactor (chat, local model server, plugin manifest, AI toolkit, QEMU sandbox, Rust runtime split into smaller files; no behavior change intended) and expanded test coverage. [Release notes](https://github.com/zeraix/zeraix/releases/tag/v2.3.3)
- **[2026-09-30 · v2.3.2]** A stability and reliability release for the Rust Agent Runtime. `allowed_tools` is now enforced inside the runtime against the resolved tool name (fixing denied tools, including write operations, executing in some automation paths), parallel-safe tool calls run in parallel again, and automation no longer falls back to another model after tools have already executed. Long-running tasks are more robust: the 10-minute per-round hard stop is removed, provider timeouts are based on idle time rather than total stream duration, and multi-byte characters split across streaming chunks are no longer corrupted. Context compaction now follows the configured `context_budget` (default 120K tokens) mid-turn, with better CJK token estimation, a fixed 1,000-token estimate per image, and interruptible summarization. Sub-agent usage is included in turn and wallet accounting, and Inspector attributes sub-agent calls by their real call IDs. A renderer crash or reload now stops the active run, and host-side tool timeouts cancel the request and withdraw its consent prompt. Also includes a refactor of the native skin/layout engine (new `visible_when` validation) and broad new test coverage. [Release notes](https://github.com/zeraix/zeraix/releases/tag/v2.3.2)
